# إدارة رصد

تطبيق React وTypeScript عربي لتحليل ملفي «رصد» و«المستودع» محليًا داخل المتصفح. يستخرج الباتشات الموجودة في رصد فقط، ويصنّفها ويتيح البحث عنها وتنزيل تقرير Excel من خمس صفحات.

## التشغيل

يتطلب Node.js 24 أو أحدث متوافق وnpm.

```bash
git clone https://github.com/mohmmed5205/rasd-manager.git
cd rasd-manager
npm install
npm run dev
```

افتح العنوان الذي يظهر في الطرفية. لا تحتاج ملف بيئة أو مفتاح API أو خادم خلفي.

```bash
npm test           # اختبارات المنطق وقراءة/كتابة Excel
npm run test:core  # اختبارات المنطق فقط؛ تعمل دون تثبيت المكتبات على Node 24
npm run build     # فحص TypeScript ثم بناء الإنتاج
npx playwright install chromium
npm run preview -- --port 4173
# في طرفية ثانية، مع استمرار preview:
npm run test:e2e
```

يعتمد اختبار المتصفح على بيانات مصطنعة منفصلة. لا توجد نتائج تجريبية مدمجة في واجهة المستخدم أو التقرير الحقيقي. يتولى GitHub Actions تثبيت المكتبات وتشغيل الاختبارات والبناء واختبار Chromium.

## الاستخدام

1. ارفع ملف رصد وملف المستودع بامتداد `.xlsx` أو `.xls`.
2. تأكد من ورقة العمل وصف العناوين. يدعم التطبيق اختيارهما يدويًا.
3. افتح «ربط الأعمدة ومعاينة البيانات» عند الحاجة. اختر الأعمدة من أسمائها وحروفها ومعاينتها؛ لا يختار التطبيق عنوانًا مكررًا تلقائيًا.
4. حدد شهر التقرير واسم الملف، ثم ابدأ التحليل.
5. راجع أخطاء المصدر والتكرارات. اختر صفًا معتمدًا لكل باتش تختلف كمياته، ثم اضغط «تطبيق الاختيارات وإعادة التحليل».
6. ابحث عن الباتش داخل أي مجموعة وافتح صفوفه الأصلية. البحث لا يغيّر محتوى التنزيل.
7. نزّل التقرير بعد معالجة الأخطاء والتعارضات. يتضمن الصفحات الخمس حتى لو كانت إحداها فارغة.

## الأعمدة

| المصدر | الحقول المطلوبة |
| --- | --- |
| رصد | BN، اسم المنتج، Quantity، Active، Quantity sent pending، Quantity Receive Pending |
| المستودع | Batch No |

GTIN اختياري. يمكن ربط أسماء أعمدة مختلفة يدويًا. جميع أعمدة رصد الأصلية محفوظة للعرض والتصدير. توحيد العناوين يتجاهل حالة الأحرف والفراغات الزائدة والشرطة السفلية، دون تغيير عنوان المصدر.

## قواعد المطابقة والتكرار

- المطابقة برقم الباتش فقط بعد `trim()` و`toUpperCase()`، دون حذف الفراغات الداخلية أو الشرطات أو الأصفار.
- يستخدم المستودع `Set`، فلا تؤثر تكراراته على عدد المطابقات.
- صفوف رصد تُجمع حسب مفتاح الباتش داخل `Map`.
- إذا تطابقت الكميات الأربع، تُحتسب مرة واحدة وتُحفظ جميع الصفوف الأصلية.
- إذا اختلفت، لا تُجمع ولا يؤخذ أكبر رقم. يجب اختيار صف معتمد؛ يحفظ التقرير رقم الصف وسبب الاعتماد.
- تُفحص أسماء المنتج في جميع الصفوف المرتبطة بالباتش للكشف عن الحقن.
- الخلايا التشغيلية الفارغة صفر. النصوص الرقمية تُحوّل، والقيم غير المفهومة أخطاء تمنع التصدير.
- العلامة العشرية هي النقطة أو `٫`. فاصل الآلاف هو `,` أو `٬` مع تجميع صحيح. الأرقام العربية والفارسية مدعومة. مثلًا `١٬٢٣٤٫٥` = `1234.5`، أما `1,5` فيحتاج تصحيحًا ولا يُخمن.
- الكميات السالبة محفوظة مع تنبيه وتخضع للشروط نفسها. الصفر التشغيلي يعني أن الأعمدة الأربعة جميعًا صفر.
- معرّفات الباتش وGTIN تُصدّر كنص. يُستفاد من تنسيق الأصفار الظاهر في Excel. إذا ضاعت دقة معرّف رقمي فلا يمكن استعادتها؛ تُحظر النتيجة حتى تصحيح المصدر.
- أخطاء معرّفات المستودع تجعل المطابقة غير موثوقة، وتمنع التصدير. الصفوف ذات الباتش الفارغ تظهر كأخطاء صفوف، ولا تتحول إلى باتش مشترك.
- الصيغ بلا قيمة محسوبة محفوظة تُعرض كأخطاء في الحقول المستخدمة؛ التطبيق لا يشغّل محرك حساب Excel. افتح المصدر واحسبه واحفظه قبل إعادة رفعه.

## التصنيف والفرز

يُستبعد أولًا الموجود في المستودع، وتُحسم التكرارات، ويُستبعد صفر الكميات الأربع. بعدها تُطبق الأولوية:

| المجموعة | الشرط | الترتيب التنازلي |
| --- | --- | --- |
| منتجات الحقن | الاسم يطابق كلمات الحقن | أكبر كمية بين Quantity وActive والإرسال والاستقبال |
| مرسل فقط | إرسال > 0 واستقبال = 0 | الإرسال |
| مستلم فقط | استقبال > 0 وإرسال = 0 | الاستقبال |
| إرسال واستقبال | كلاهما > 0 | مجموع الإرسال والاستقبال |
| Active فقط | إرسال واستقبال = 0 وActive > 0 | Active |

عند التساوي يُستخدم مفتاح الباتش تصاعديًا بمقارنة نصية ثابتة لا تعتمد على لغة الجهاز. كلمات الحقن وحدود الكشف قابلة للتعديل في `src/config/rules.ts`.

باتش Quantity فقط، مثلًا، لا يدخل Active تلقائيًا؛ يظهر كغير مصنف مع تفسير. تعرض الواجهة تفاصيل الصفر وغير المصنف والأخطاء والمعادلة:

`باتشات رصد فقط = مصنف + صفر الكميات + غير مصنف + تعارضات معلقة + باتشات بها أخطاء`

تُحسب صفوف المعرّفات غير الصالحة منفصلة عن الباتشات الفريدة. نتائج وجود أخطاء أو تعارضات مؤقتة حتى مراجعتها.

## ملف التقرير

كل صفحة تبدأ بالشهر والمجاميع وقاعدة التكرار وملخص الحالات المستبعدة. يليها جدول باتشات فريدة، بالكميات المعتمدة وكمية الترتيب وعدد الصفوف الأصلية وبيانات الصف المعتمد. بعده جدول منفصل بجميع صفوف وأعمدة المصدر الأصلية. لا تجمع جدول التفاصيل مع الجدول المعتمد.

تفاصيل المستبعد وغير المصنف وتنبيهات المصدر موجودة أسفل صفحة منتجات الحقن. مجاميع المجموعات لا تتأثر بالبحث. يحتفظ التقرير بالنظام الأصلي لتواريخ Excel (1900 أو 1904) وتنسيقات التواريخ الرقمية، دون تخمين أن أي رقم هو تاريخ.

تُنسخ قيم الخلايا وتنسيقاتها الرقمية؛ لا تُنسخ الصيغ التنفيذية أو وحدات الماكرو أو تنسيقات المصنف الأصلية بالكامل. يدعم التصدير عرض الأعمدة والتصفية؛ لا ندعي تجميد العناوين لأن دعم تصديرها غير موثوق في SheetJS CE.

## البنية

```text
src/
  App.tsx                       تنسيق سير العمل وحالة الواجهة
  main.tsx                      نقطة التشغيل وحد التعامل مع أخطاء العرض
  types.ts                      أنواع البيانات ورسائل Worker
  config/rules.ts               المجموعات والأعمدة والكلمات والحدود
  lib/analysis.ts               التنظيف والتحقق والمطابقة والتكرار والتصنيف والمجاميع
  lib/excel.ts                  قراءة Excel ومعاينته وتوليد التقرير
  hooks/useAnalysisWorker.ts    إدارة Worker والطلبات والإلغاء
  workers/analysis.worker.ts    تنفيذ القراءة والتحليل والتصدير خارج الواجهة
  components/
    FilePanel.tsx               رفع الملف واختيار الورقة وربط الأعمدة
    Results.tsx                 الجداول والبحث والمجاميع والاستبعادات
    Review.tsx                  الأخطاء واعتماد التكرارات
    ui.tsx                      عناصر مشتركة وأيقونات SVG وتنسيقات inline
tests/
  core.test.ts                  قواعد المطابقة والكميات والتصنيف
  excel.test.ts                 إعادة قراءة التصدير والتواريخ والأنواع
  ui.e2e.mjs                    تجربة مستخدم فعلية في Chromium
```

تستخدم التنسيقات `style` داخل العناصر أو كائنات تنسيق في ملف المكوّن نفسه. التخطيط مرن باستخدام flex-wrap، مع تمرير أفقي داخل الجداول فقط. لا توجد ملفات CSS أو طلبات خطوط خارجية. تُترك حدود تركيز المتصفح الأصلية لتسهيل استخدام لوحة المفاتيح.

## الأداء والخصوصية

القراءة والمطابقة والتصنيف وتوليد Excel تتم داخل Web Worker. تتبادل الواجهة رسائل TypeScript محددة الأنواع. ينقل ملف التصدير كـArrayBuffer قابل للتحويل. لا توجد تحليلات استخدام أو API خارجي في وقت التشغيل.

تُعرض النتائج على صفحات، وتُعرض الصفوف الأصلية عند الطلب. حدود النسخة: 100 ميجابايت لكل ملف، 300 ألف صف، 512 عمودًا لكل ورقة. هذه حدود وقائية وليست ضمانًا لقدرة كل جهاز؛ المصنفات المضغوطة قد تحتاج ذاكرة أكبر بكثير من حجمها. Worker يحافظ على استجابة الواجهة لكنه لا يلغي حد الذاكرة.

تغيير الملفات أو الورقة أو صف العناوين أو الربط يمسح النتائج السابقة. تغيير اعتماد التكرار يعطل التصدير حتى إعادة التحليل. زر إعادة التهيئة ينهي Worker ويزيل بياناته من الذاكرة. لا يُستخدم localStorage أو IndexedDB لتخزين الملفات.

## النشر

`npm run build` ينتج مجلد `dist` القابل للنشر على أي استضافة ثابتة. `base: './'` يسمح أيضًا باستضافة المشروع تحت مسار مستودع. يمكنك نشر المستودع على Vercel أو Netlify بإعداد build = `npm run build` وoutput = `dist`، دون متغيرات بيئة.

لا يوجد نشر تلقائي قبل اختيار الاستضافة. سير GitHub Actions يرفق نسخة `dist` باسم `rasd-manager-build` بعد نجاح جميع الفحوص. يجب تثبيت المكتبات بنجاح قبل تشغيل الواجهة أو اختبارها. مصدر SheetJS الرسمي: https://docs.sheetjs.com/docs/getting-started/installation/nodejs/

## نطاق التحقق

اختبارات المنطق تعمل على Node دون الحاجة إلى React. اختبارات Excel تحتاج SheetJS، واختبار الواجهة يحتاج تشغيل preview وChromium. لا توجد ملفات مستخدم حقيقية مرفقة بهذا المستودع، لذلك يجب إجراء تجربة قبول نهائية على ملفاتك الشهرية والتحقق من أسماء الأعمدة والنتائج قبل اعتماد التقرير تشغيليًا.
